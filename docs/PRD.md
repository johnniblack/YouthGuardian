V1.0

# 1. 项目背景

YouTube、Bilibili 等视频网站的搜索结果页、首页推荐、侧边推荐中会混入大量不适合儿童及青少年观看的内容。
仅靠搜索关键词无法控制平台后续推荐内容，也无法保证孩子只看指定频道的视频。

本产品拟开发一个 Chrome 插件，用于在视频网站中建立“**频道白名单**”机制。家长可先搜索孩子可观看的内容，再通过插件把可信频道加入允许列表。开启限制后，页面只展示来自允许频道的视频，其他视频内容全部隐藏。

同时，为避免儿童自行关闭限制或删除白名单，插件需增加**本地密码保护机制**。

---

# 2. 产品目标

## 2.1 核心目标
实现一个面向家长/监护人的浏览器插件，使视频网站页面仅展示来自**允许频道列表**的视频内容。

## 2.2 产品价值
- 帮助儿童和青少年只接触经过家长筛选的频道内容
- 降低平台推荐算法带来的内容失控风险
- 提供简单、低门槛的本地化家长控制能力
- 无需服务器，不依赖账号体系，数据仅保存在本地

## 3.2 被管控对象
- 儿童
- 青少年（尤其 16 岁以下）

# 4. 使用场景

## 场景一：搜索教育内容后建立白名单
家长在 YouTube/Bilibili 搜索“儿童英语”“初中物理”“科学实验”等关键词，打开插件后查看当前页面视频列表，将可信频道加入允许列表，再开启限制。

## 场景二：孩子日常浏览受限内容
白名单已建立后，孩子打开 YouTube/Bilibili 时，插件自动过滤页面，仅展示允许频道的视频卡片。

## 场景三：家长管理频道白名单
家长可在插件中查看所有已允许频道，并对其进行删除、清空等管理。

## 场景四：防止孩子自行关闭限制
插件通过本地密码保护“解除限制”“删除白名单”“清空白名单”“修改密码”等高风险操作，避免未授权操作。

# 7. 功能需求详述

---

## 7.1 当前页面可见视频扫描

### 7.1.1 功能描述
用户在 YouTube 或 Bilibili 页面点击插件图标后，插件应读取当前页面中可识别的可见视频卡片，并在 popup 中展示列表。

### 7.1.2 展示字段
每条视频信息至少包含：
- 视频标题
- 频道名 / UP 主名
- 视频时长
- 平台标识（YouTube / Bilibili）
- 视频链接（可内部存储，不强制展示）

### 7.1.3 扫描范围
MVP 优先支持以下页面中的标准视频卡片：
- 搜索结果页
- 首页推荐视频流
- 侧边推荐区（若可稳定解析）
- 频道页视频列表（若可稳定解析）

### 7.1.4 扫描规则
- 仅处理页面中已加载的标准视频卡片
- 优先识别有标题、频道名、时长的内容
- 对广告、直播、特殊卡片、短视频可先忽略

### 7.1.5 异常处理
若当前页面未识别到视频，应提示：
- 当前页面未识别到可管理视频
- 请刷新后重试
- 或当前页面暂不支持

### 7.1.6 验收要求
- 在 YouTube/Bilibili 常规搜索结果页中，能够识别大多数标准视频卡片
- 列表中至少展示标题、频道名、时长

---

## 7.2 允许频道添加

### 7.2.1 功能描述
在当前页面视频列表中，用户可以点击“允许此频道”将该视频所属频道加入允许列表。

### 7.2.2 操作逻辑
- 允许对象是**频道/UP 主**
- 不是允许单个视频
- 同一频道只需添加一次

### 7.2.3 按钮状态
- 未加入白名单：显示 `允许此频道`
- 已加入白名单：显示 `已允许`

### 7.2.4 数据要求
允许频道记录应至少包含：
- 平台
- 频道显示名
- 频道唯一标识（如可获取）
- 频道主页链接（如可获取）
- 添加时间
- 添加来源

### 7.2.5 唯一识别策略
白名单匹配优先级：
1. 平台 + authorId
2. 平台 + authorUrl
3. 平台 + authorName

### 7.2.6 验收要求
- 点击“允许此频道”后，频道立即进入允许列表
- 重复添加同一频道不应产生重复记录

---

## 7.3 已允许频道列表管理

### 7.3.1 功能描述
插件应提供“已允许频道”列表，方便统一查看和管理所有允许频道。

### 7.3.2 展示字段
每条记录包含：
- 平台
- 频道名 / UP 主名
- 添加时间（可选）
- 删除按钮

### 7.3.3 操作能力
用户可进行：
- 查看全部已允许频道
- 删除某条允许频道
- 清空全部允许频道（建议提供）
- 搜索频道名（可选）

### 7.3.4 删除后的效果
若限制模式已开启，删除频道后应立即重新过滤当前页面，相关内容不再展示。

### 7.3.5 验收要求
- 用户可成功删除指定频道
- 删除后数据持久化更新
- 当前页面过滤状态同步变化

---

## 7.4 限制观看 / 解除限制

### 7.4.1 功能描述
插件提供一个全局限制开关，决定是否在支持网站中执行白名单过滤。

### 7.4.2 状态定义
- 限制观看：开启
- 限制观看：关闭

### 7.4.3 开启限制后的效果
在 YouTube/Bilibili 页面中，仅展示来自允许频道的视频卡片，其余视频卡片全部隐藏。

### 7.4.4 关闭限制后的效果
页面恢复原始内容展示，不再隐藏非白名单视频。

### 7.4.5 状态持久化
限制开关状态需保存在本地，浏览器关闭、刷新页面、重新打开后仍保持。

### 7.4.6 生效范围
MVP 建议采用全局统一开关：
- 开启后，对所有支持的网站生效
- 不区分单独平台开关

### 7.4.7 验收要求
- 开启限制后当前页面立即生效
- 刷新页面后限制状态依旧有效
- 关闭限制后页面恢复正常显示

---

## 7.5 页面自动过滤执行

### 7.5.1 功能描述
当限制模式开启时，插件应自动识别页面中的视频卡片，并根据频道是否在白名单中决定显示或隐藏。

### 7.5.2 过滤规则
- 白名单频道：保留显示
- 非白名单频道：隐藏
- 无法识别频道信息的卡片：默认隐藏更安全

### 7.5.3 生效时机
过滤逻辑需在以下时机触发：
- 页面初次加载完成
- 搜索结果更新
- 页面滚动懒加载
- 路由变化（YouTube / Bilibili 的 SPA 行为）

### 7.5.4 实现要求
- 使用 `MutationObserver` 监听 DOM 变化
- 做节流处理，避免频繁全量扫描
- 对已处理元素进行标记，减少重复处理

### 7.5.5 视觉策略
MVP 直接隐藏不符合条件的视频卡片即可，不必展示占位提示。

### 7.5.6 验收要求
- 新加载的视频卡片会被继续过滤
- 页面跳转后过滤仍然有效
- 不应出现明显卡顿

---

## 7.6 本地密码保护

### 7.6.1 功能目标
为了防止儿童自行关闭限制或篡改允许频道列表，插件需支持**本地密码保护**。
密码不依赖服务器，不做账号系统，仅保存在本地。

### 7.6.2 保护范围
以下操作必须输入密码验证后才允许执行：

#### 必须受保护的操作
1. 解除限制观看
2. 删除已允许频道
3. 清空全部允许频道
4. 重置/修改密码
5. 关闭密码保护（如支持）

#### 可选受保护操作
1. 开启限制观看
通常开启限制风险较低，可不要求密码。MVP 可不强制。

### 7.6.3 首次设置密码
当用户第一次使用插件时：
- 若尚未设置密码，插件应引导用户设置本地管理密码
- 需输入两次确认
- 密码长度建议至少 4 位，推荐 6 位以上

### 7.6.4 密码存储要求
- 密码不能以明文形式保存
- 应保存为本地哈希值
- 使用浏览器内置 Web Crypto API 做摘要处理
- 数据保存在 `chrome.storage.local`

### 7.6.5 密码输入交互
当用户执行受保护操作时：
- 弹出密码输入区域 / 弹窗
- 输入正确后继续执行操作
- 输入错误则提示“密码错误”

### 7.6.6 修改密码
用户可在插件设置中执行修改密码：
- 输入旧密码
- 输入新密码
- 再次确认新密码
- 验证通过后更新本地哈希

### 7.6.7 忘记密码
MVP 阶段不做找回服务，因为无服务器。
可定义为：
- 忘记密码后只能通过“清空插件本地数据”的方式重置
- 清空后会丢失白名单与配置
- 需在产品中明确提示

### 7.6.8 安全边界说明
该密码保护是“本地插件级保护”，主要用于防止儿童误操作或普通绕过，不等同于系统级安全控制。
如用户有浏览器管理员权限，仍可能通过禁用插件等方式绕过。

### 7.6.9 验收要求
- 首次可正确设置密码
- 受保护操作必须先验证密码
- 密码不能明文保存
- 修改密码流程可用
- 本地重装插件后密码随本地数据一并丢失

## 7.7 插件弹窗 UI

### 7.7.1 页面结构
建议 popup 包含以下区域：

#### 区域 A：顶部状态
- 当前网站：YouTube / Bilibili / 不支持
- 限制状态：已开启 / 已关闭

#### 区域 B：主操作
- 开启限制观看
- 解除限制观看

#### 区域 C：当前页面视频列表
- 标题：当前页面可见视频
- 每条内容显示：
  - 标题
  - 频道名
  - 时长
  - 按钮：允许此频道 / 已允许

#### 区域 D：已允许频道
- 标题：已允许频道
- 每条记录显示：
  - 平台 + 频道名
  - 删除按钮

#### 区域 E：密码与设置
- 设置密码 / 修改密码
- 清空白名单
- 说明文案

### 7.7.2 空状态
- 当前页面不支持
- 当前未识别到视频
- 尚无允许频道
- 尚未设置密码

### 7.7.3 验收要求
- popup 结构清晰，能在常见桌面浏览器宽度下正常显示
- 各功能区域可独立操作
- 交互反馈明确

# 8. 非功能需求

## 8.1 性能
- popup 打开后 1~2 秒内完成当前页面扫描
- 过滤逻辑对页面滚动不造成明显卡顿
- DOM 监听需做节流/去抖处理

## 8.2 稳定性
- 单个视频卡片解析失败不应导致整体功能失效
- 对 YouTube/Bilibili 分别维护解析规则
- 插件刷新、页面跳转后应保持稳定工作

## 8.3 隐私与数据
- 不上传任何用户数据到服务器
- 所有数据存储在本地 `chrome.storage.local`
- 不要求用户登录
- 不采集浏览记录做远程分析

## 8.4 可维护性
- 站点解析逻辑模块化
- 白名单匹配逻辑统一封装
- 存储和消息通信独立封装
- 密码校验逻辑与 UI 分离

# 10. 业务规则

## 10.1 白名单优先原则
仅允许白名单频道内容展示，其他频道默认不展示。

## 10.2 平台隔离原则
- YouTube 白名单仅作用于 YouTube
- Bilibili 白名单仅作用于 Bilibili

## 10.3 频道匹配优先级
匹配优先顺序：
1. `platform + authorId`
2. `platform + authorUrl`
3. `platform + authorName`

## 10.4 不可识别内容处理
对无法识别频道信息的视频卡片，默认隐藏。

## 10.5 密码保护原则
任何会降低限制强度或修改控制范围的关键操作，都应要求密码验证。

# 11. 典型用户流程

## 11.1 首次使用流程
1. 安装插件
2. 打开 YouTube/Bilibili
3. 点击插件
4. 设置本地管理密码

2. 点击某允许频道的删除按钮

5. 当前页面即时重新过滤

1. 家长点击“解除限制观看”
2. 输入密码
3. 验证成功后关闭限制

# 15. 风险与边界

## 15.1 网站 DOM 变动
YouTube/Bilibili 页面结构更新可能导致选择器失效，需预留维护能力。

## 15.2 安全边界有限
本地密码仅能防止一般误操作和普通绕过，无法阻止用户停用插件或删除插件。

## 15.3 唯一 ID 获取不稳定
某些卡片可能无法获取稳定频道 ID，需要 URL 或名称兜底。

## 15.4 首屏闪现问题
页面内容可能先显示后被隐藏，MVP 可接受，后续可优化为先遮罩后渲染。

# 16. 验收标准

## 16.1 视频扫描
- 在 YouTube/Bilibili 常规页面可识别多数标准视频卡片
- popup 中能展示标题、频道名、时长

## 16.2 白名单添加
- 点击“允许此频道”后成功加入本地白名单
- 重复添加不重复记录

## 16.3 白名单管理
- 可查看已允许频道
- 可删除单条频道
- 删除后页面重新应用过滤

## 16.4 限制开关
- 开启限制后页面立即过滤
- 刷新后状态保持
- 解除限制后页面恢复显示

## 16.5 动态过滤
- 滚动新增内容也会继续过滤
- 搜索切换、路由变化后仍有效

## 16.6 密码保护
- 首次可设置密码
- 解除限制必须验证密码
- 删除白名单必须验证密码
- 清空白名单必须验证密码
- 密码不以明文存储
